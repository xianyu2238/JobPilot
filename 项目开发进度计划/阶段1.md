# 阶段 1：简历解析、JD 匹配与基础页面

**目标：** 完成“上传简历 → 查看解析结果 → 粘贴 JD → 直接分析”的基础闭环。本文件只说明功能和验收要求，具体实现开发时再确定。

**状态：** 功能代码已实现，自动化与本地启动检查通过；真实模型已通过合成 PDF、PNG 解析验证，完整九组人工准确性验收仍待完成。启动和新增文件清单见 [阶段 1 使用说明](../docs/阶段1使用说明.md)。

## 1. 基础页面

本阶段就构建可操作的 Streamlit 页面，与后端接口联通。

| 区域 | 内容 |
| --- | --- |
| 左侧侧边栏 | 项目名称、当前入口“简历与岗位匹配”；预留 Agent 助手、岗位调研、模拟面试、知识库、历史记录 |
| 左侧主栏 | 简历上传、自动解析、五类可编辑表单、保存与确认 |
| 右侧主栏 | 目标 JD、分析按钮、简要匹配度、简历修改建议和学习计划 |

侧边栏中的预留入口统一标记“待实现”，禁用或点击后仅展示说明，不显示虚假的可用功能。Agent 助手在阶段 2 接入，其余功能按后续阶段逐步开放。

页面需要显示处理中、成功和失败状态；替换简历或修改 JD 后，旧匹配结果失效。简历解析核对完成并填写 JD 后才能开始分析。

**简历信息表单：** 整理结果直接填入个人信息、教育背景、实习经历、项目经历和个人技能。每条记录使用独立文本表单，项目等长内容采用多行文本框，移除来源展示和模型发送勾选，保留保存与核对确认。

## 2. 简历上传与解析

- 支持 **PDF、PNG、JPG/JPEG**，包括文本型 PDF、扫描型 PDF 和简历截图。
- 文本型 PDF 提取文字；PNG/JPG/JPEG 和扫描型 PDF 默认通过本地 OCR 获取内容，远程视觉模型为手动备用。
- 校验文件真实格式、大小及 PDF 页数/图片尺寸；损坏、加密或无法识别的文件返回明确提示。
- 按个人信息、教育背景、实习经历、项目经历和个人技能整理，支持编辑、增删、保存，并保留原文对照。
- 不编造缺失信息；识别不清或内容不完整时提示核对，不直接判断用户缺少能力。

## 3. 岗位信息来源

用户从企业招聘官网、招聘平台等渠道复制 JD，粘贴到页面后直接开始分析。系统不自动获取岗位，独立的岗位要求抽取与预览功能已移除。

## 4. 匹配分析

- **简要匹配度分析：** 用简短文字概括整体匹配程度、主要优势和关键差距，不展示缺乏依据的百分比。
- **简历修改建议（重点）：** 指出需要调整的具体段落、修改原因和表达方向；必要时提供基于已有事实的改写示例，不编造经历或数据。
- **学习建议（重点）：** 针对岗位关键差距，按优先级给出学习主题、练习任务及预期成果，说明先学什么、如何练习。
- 建议结合岗位要求和简历证据；区分“已有经历但表达不足”与“需要确认或补充的能力”，避免把简历未提及直接当作不会。
- 识别不清或信息不足时提示核对，避免基于不确定内容给出确定结论。

## 6. 验收标准

- 能在基础页面跑通上传、解析、输入 JD、匹配分析的完整流程。
- 侧边栏展示当前功能及待实现入口，状态清晰。
- 至少使用 3 份脱敏简历和 3 份 JD 验证，简历样例覆盖文本型 PDF、扫描型 PDF、PNG。
- 结构化结果通过验证；匹配结论有可核对的依据；识别不清时有明确提示。
- 能对照原文件核对并修改信息；未保存或未确认时不能开始匹配，保存后分析使用新版本。
- 匹配度概述简短清楚；修改建议指向具体内容，学习建议有优先级和可执行任务。
- 无效文件、模型调用失败等情况不会产生虚假的成功结果。
- 自动化测试通过，记录真实模型与图片识别的验证结果；尚未完成的验证如实说明。

**验证记录：** 本地密集图片 OCR 已实测通过，合成简历模型整理已返回五类信息。自动化覆盖编辑保存、版本冲突、重新确认和新版本分析；完整九组人工准确性核对仍待完成。最新运行方法与实测耗时见阶段 1 使用说明。
